## Remaining limits and findings
These checks do not establish production security or exhaustive correctness.
- **P1: synthetic execution.** The current runner simulates LLM output, boundary checks, latency, and teardown. The containers contain sleeping Alpine processes, not actual model workers. The interface now states this. Real model inference, firewall enforcement, side-channel resistance, rootless operation and kernel attestations remain unverified.
- **P1: administrative API access.** Dispatch, paired tests and tamper endpoints have no authentication or authorization. CORS is now restricted, but CORS is not an authorization boundary. Deploy behind authenticated access before using outside a trusted local environment.
- **P2: live TinyFish service.** API key presence is configuration only. No paid automation or live external canary exfiltration was performed. Remote endpoint compatibility and successful authenticated automation require a separate live integration check.
- **P2: container runtime.** Docker Desktop's Linux engine was unavailable. Dockerfile image builds and runtime network/seccomp checks were not executed.
- **P2: scale.** Ledger verification and paired lookup currently scan all stored rows. This favors correctness for the local workbench but needs pagination/caching and load testing for large ledgers. Checkpoint export still retains the latest 500 runs.
- **P2: ledger threat model.** Receipts attest records; the SQLite file is mutable and individual receipts alone do not prove that records were never deleted or reordered. Independent public-key trust and externally anchored checkpoints remain necessary.
- **P3: upstream warning.** The test client emits an upstream AnyIO/Starlette deprecation warning; tests pass.
- Existing README and DESIGN statements about live metrics, immutable storage, production guarantees, and measured AAA contrast should be read alongside these findings. No formal WCAG conformance or real-device motion audit was performed.

## Run locally
1. In web, run npm ci, then npm run dev.
2. At the repository root, run python -m services.mediator.app.
3. Browser requests use /api through Next.js. The default mediator is http://127.0.0.1:8000. Set MEDIATOR_URL before a build when changing the upstream address.
4. Run python -m pytest harness -q for the backend suite.
5. Run npm run build and npm audit --omit=dev inside web.
6. With Docker's Linux engine running, use docker compose build and docker compose up. The frontend build receives http://mediator:8000 as MEDIATOR_URL.
